# 清美教育管理系统 - 面试问答手册

## 项目基础问题

### Q1: 请介绍一下这个项目
**A**: 清美教育管理系统是我参与开发的一个教育培训机构一体化管理平台。项目采用前后端分离架构，前端使用React 19 + TypeScript，后端使用FastAPI + Python 3.12，数据库使用PostgreSQL 17。系统覆盖学术、咨询、市场、人力等全业务流程，支持10+校区、500+用户，管理100万+条数据。我主要负责咨询部核心功能、性能优化和权限系统重构。

### Q2: 项目的技术栈是什么？为什么选择这些技术？
**A**:
- **前端**：React 19（并发特性提升性能）+ TypeScript（类型安全）+ Vite（极速构建）+ Ant Design 5（企业级UI）
- **后端**：FastAPI（高性能异步框架）+ Python 3.12（最新特性）+ SQLAlchemy 2.0（ORM）
- **数据库**：PostgreSQL 17（支持JSONB、全文搜索、GIN索引）

选择理由：FastAPI性能接近Node.js和Go，自动生成API文档；PostgreSQL的JSONB字段非常适合存储动态配置；React 19的并发特性显著提升了大数据量表格的渲染性能。

### Q3: 项目规模有多大？
**A**:
- 代码量：前端约8万行、后端约5万行
- 用户规模：10+校区、500+用户、日活300+
- 数据规模：100万+条记录、日增5000+条
- 功能模块：5大核心模块、80+功能页面
- API接口：200+个RESTful接口

### Q5: 遇到的最大技术难点是什么？如何解决的？
**A**: 最大的难点是**PostgreSQL JSONB字段查询性能问题**。

**问题背景**：当面标准化检查表使用JSONB存储16步咨询内容，初期按步骤内容搜索时查询耗时5-8秒，用户体验极差。

**解决方案**：
1. **创建GIN索引**：`CREATE INDEX idx_jsonb_content ON table USING GIN (steps_content);`
2. **优化查询操作符**：从`->>` JSON提取改为`@>` JSON包含操作符，充分利用GIN索引
3. **热数据分离**：将常用查询字段（如咨询师、日期）提取为独立列，减少JSONB查询
4. **查询优化**：使用`EXPLAIN ANALYZE`分析执行计划，调整查询策略

**效果**：查询时间从5-8秒降至200-300毫秒，性能提升95%。

**技术要点**：
- GIN索引适合JSONB、数组、全文搜索
- `@>`操作符比`->>`更高效，因为可以使用索引
- 热数据分离是常见的性能优化手段

### Q6: 如何解决前端大数据量表格渲染卡顿问题？
**A**: 教员功能分析表有2000+行数据，初期滚动时FPS降至15，非常卡顿。

**解决方案**：
1. **虚拟滚动**：使用`react-window`库，只渲染可见区域的行（约20-30行），而不是全部2000行
2. **分页加载**：后端分页，前端缓存已加载数据，按需加载更多
3. **防抖优化**：搜索、筛选操作防抖300ms，减少不必要的渲染
4. **React.memo优化**：对表格行组件使用memo，避免父组件更新时子组件不必要的重渲染
5. **列虚拟化**：对于列数很多的表格，也实现列级别的虚拟滚动

**效果**：FPS从15提升至60，滚动流畅度提升300%，内存占用降低80%。

### Q7: 如何实现多校区数据隔离？
**A**: 系统支持10+校区，需要确保数据隔离（校区A看不到校区B的数据），同时管理中心需要聚合所有校区数据。

**解决方案**：
1. **数据库层**：所有业务表增加`campus_id`字段，创建复合索引`(campus_id, created_at)`
2. **后端中间件**：JWT解析后自动注入`campus_id`过滤条件，普通用户只能查询自己校区的数据
3. **权限校验**：双重校验（JWT令牌 + 数据库行级权限），防止绕过
4. **聚合查询**：管理中心角色使用`GROUP BY campus_id`聚合，或者不注入`campus_id`过滤条件

**关键代码**（后端中间件）：
```python
async def inject_campus_filter(request: Request, call_next):
    user = get_current_user(request)
    if user.role != "admin":  # 非管理员
        request.state.campus_id = user.campus_id
    return await call_next(request)
```

**效果**：数据隔离100%，0次跨校区访问；聚合查询性能<500ms。

### Q8: JWT令牌过期问题如何解决？
**A**: 初期JWT令牌有效期30分钟，用户操作超过30分钟后需要重新登录，体验很差。

**解决方案 - Refresh Token机制**：
1. **双令牌设计**：Access Token（30分钟）+ Refresh Token（7天）
2. **自动刷新**：前端axios拦截器检测401响应，自动调用刷新接口
3. **无感刷新**：刷新过程用户无感知，不中断当前操作
4. **密钥轮换**：支持多密钥并存，平滑过渡，提升安全性

**关键代码**（前端拦截器）：
```typescript
axios.interceptors.response.use(
  response => response,
  async error => {
    if (error.response?.status === 401) {
      const newToken = await refreshToken();
      error.config.headers.Authorization = `Bearer ${newToken}`;
      return axios.request(error.config);  // 重试原请求
    }
    return Promise.reject(error);
  }
);
```

**效果**：用户7天内无需重新登录，登录频率降低95%。

## 架构设计问题

### Q9: 系统的整体架构是怎样的？
**A**: 系统采用**前后端分离 + 微服务化**架构：

```
用户浏览器
    ↓
Nginx (反向代理 + 负载均衡 + HTTPS)
    ↓
前端服务 (React SPA)
    ↓ API请求
后端服务 (FastAPI)
    ↓
PostgreSQL (主从复制)
```

**关键设计**：
1. **前后端分离**：前端独立部署，通过RESTful API通信
2. **多环境隔离**：dev（开发）、test（测试）、prod（生产）三套环境
3. **数据库多Schema**：academic（学术）、consult（咨询）、market（市场）逻辑隔离
4. **安全层级**：JWT认证 → RBAC权限 → 数据过滤 → 审计日志

### Q10: 如何保证系统安全性？
**A**: 系统实施了**多层安全防护**：

**1. 认证层**
- JWT + HttpOnly Cookie：防止XSS攻击窃取令牌
- Refresh Token机制：短期Access Token + 长期Refresh Token
- 密钥轮换：支持多密钥并存，定期更换

**2. 权限层**
- RBAC权限系统：角色-权限-菜单三级控制
- 数据权限隔离：多校区数据100%隔离
- 最小权限原则：用户只能访问必要的资源

**3. 防护层**
- 限流中间件：100次/分钟，防止暴力攻击
- CORS严格配置：只允许白名单域名跨域
- SQL注入防护：使用ORM参数化查询
- XSS防护：前端输入过滤 + 后端输出转义

**4. 审计层**
- 操作日志：记录所有敏感操作（增删改）
- 登录日志：记录登录时间、IP、设备
- 数据变更历史：关键数据保留变更记录

**效果**：通过渗透测试，0个安全漏洞。

### Q14: 遇到过什么印象深刻的Bug？
**A**: **Windows编码问题导致的数据乱码**。

**问题**：Windows系统默认GBK编码，Python读取中文文件名、中文内容时出现乱码，导致数据导入失败。

**排查过程**：
1. 发现只在Windows环境出现，Linux正常
2. 使用`chardet`库检测文件编码，发现是GBK
3. 查看Python默认编码：`sys.getdefaultencoding()` 返回 `utf-8`，但实际读取时使用了系统编码

**解决方案**：
1. 统一UTF-8：所有文件强制UTF-8编码
2. 环境变量：设置`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`
3. 文件读写：显式指定`encoding='utf-8'`
4. 数据库连接：PostgreSQL连接字符串指定`client_encoding=utf8`

**教训**：跨平台开发必须注意编码问题，显式指定编码比依赖默认值更可靠。
