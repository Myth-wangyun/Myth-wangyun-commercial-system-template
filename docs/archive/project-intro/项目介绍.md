# 清美教育管理系统 - 项目介绍

## 一、业务和功能介绍

### 1. 立项背景和目标

清美教育管理系统（QM System）是为教育培训机构打造的一体化管理平台。项目立项背景源于传统教育培训机构在日常运营中面临的多重挑战：学员信息分散、教学质量难以量化、咨询转化率低、多校区数据孤岛、业绩考核不透明等问题。系统目标是通过数字化手段实现教学、咨询、市场、人力等全业务流程的标准化管理，提升运营效率，降低管理成本，最终实现数据驱动的精细化运营。

### 2. 软件功能与核心模块

系统采用模块化设计，覆盖教育培训机构的全业务场景，主要包含以下核心功能模块：

#### 2.1 学术部管理模块
- **教员管理**：教员KPI自动计算、功能分析（听课、违纪、项目合格率）、课时统计、年度听课打分
- **教学质量管理**：作业成绩登记、考试成绩管理、项目成绩横向对比、压力面试成绩
- **学员管理**：学员满意度调查、访谈记录、稳定性追踪、新生流失明细
- **口碑招生**：个人/校区目标与结果汇总、月度统计、报名明细、关键点结果追踪
- **就业管理**：班级就业信息、教员就业汇总、就业明星、薪资预估、就业追踪

#### 2.2 咨询部管理模块
- **咨询量管理**：咨询量录入、统计分析、保护期管理、转量管理、交接管理
- **标准化检查**：当面标准化检查表（16个标准咨询步骤）、电话标准化检查表
- **咨询师管理**：咨询师列表、月度计划、数据汇总（V1/V2/V3版本）、归属管理
- **沟通记录**：咨询沟通记录、电话量统计、缴费记录管理
- **人力管理**：入职离职明细、员工访谈、会议记录、培训周度/月度表、职数管理

#### 2.3 校区管理模块
- **核心数据汇总**：就业、口碑、稳定性、培训计划、入职离职等核心指标
- **目标与结果管理**：就业目标与结果、口碑招生目标与结果、月度个人目标
- **学员稳定性**：新生维稳个人/月度汇总、新生流失明细、欠费明细
- **企业文化**：企业文化宣讲计划、考试计划、课程安排

#### 2.4 市场部管理模块
- **百度营销API集成**：OAuth认证、数据同步、广告投放数据分析
- **渠道管理**：渠道代理数据、媒体来源配置、人群数据分析

#### 2.5 权限与审计模块
- **RBAC权限系统**：角色权限管理、菜单权限控制、数据权限隔离
- **审计日志**：操作日志记录、敏感操作追踪、数据变更历史
- **多校区支持**：校区信息管理、数据隔离、跨校区数据汇总

### 3. 业务流程与功能路径

#### 3.1 咨询招生流程
```
咨询量录入 → 保护期管理 → 咨询沟通记录 → 缴费记录 → 报名明细 → 新生安排
```
咨询师通过系统录入咨询量，系统自动计算保护期，记录每次沟通内容和电话量，学员缴费后生成报名明细，最终安排到具体班级。

#### 3.2 教学管理流程
```
排课表 → 作业成绩登记 → 考试成绩管理 → 项目成绩登记 → 学员满意度调查 → 压力面试 → 就业追踪
```
教务人员制定排课表，教员录入作业、考试、项目成绩，定期进行学员满意度调查，临近毕业进行压力面试，最后进行就业追踪和薪资预估。

#### 3.3 教员考核流程
```
课时统计 → 功能分析（听课/违纪/合格率） → 学员满意度 → KPI自动计算 → 业绩奖惩
```
系统自动统计教员课时，汇总功能分析各项指标，结合学员满意度，自动计算KPI得分，生成业绩奖惩表。

#### 3.4 校区运营流程
```
月度目标设定 → 日常数据录入 → 核心数据汇总 → 目标达成分析 → 管理决策
```
校区管理者设定月度目标（就业、口碑、稳定性），各部门日常录入数据，系统自动汇总核心数据，对比目标达成情况，为管理决策提供数据支持。

## 二、项目实现

### 1. 整体架构与技术栈

#### 1.1 系统架构
系统采用前后端分离架构，前端使用React构建SPA应用，后端使用FastAPI提供RESTful API服务，PostgreSQL作为数据持久化层。

```
┌─────────────────────────────────────────────────────────┐
│                      前端层 (Frontend)                    │
│  React 19 + TypeScript + Vite + Ant Design 5            │
│  Zustand (状态管理) + React Query (数据获取)              │
├─────────────────────────────────────────────────────────┤
│                      API网关层                            │
│  Nginx (反向代理 + 负载均衡 + HTTPS)                      │
├─────────────────────────────────────────────────────────┤
│                      后端层 (Backend)                     │
│  FastAPI + Python 3.12 + Pydantic                       │
│  JWT认证 + RBAC权限 + 审计日志                            │
├─────────────────────────────────────────────────────────┤
│                      数据层 (Database)                    │
│  PostgreSQL 17 + SQLAlchemy 2.0                         │
│  多Schema设计 (academic/consult/market)                  │
└─────────────────────────────────────────────────────────┘
```

#### 1.2 技术栈详解

**前端技术栈**
- **React 19**：最新版本，利用并发特性提升性能
- **TypeScript**：类型安全，减少运行时错误
- **Vite**：极速构建工具，HMR响应时间<50ms
- **Ant Design 5**：企业级UI组件库，支持主题定制
- **Zustand**：轻量级状态管理，比Redux简洁30%代码
- **React Query**：服务端状态管理，自动缓存和重新验证
- **Recharts**：数据可视化，支持响应式图表
- **ExcelJS + html2canvas**：数据导出（Excel/图片）

**后端技术栈**
- **FastAPI**：高性能异步框架，性能接近Node.js和Go
- **Python 3.12**：最新特性，性能提升15%
- **SQLAlchemy 2.0**：ORM框架，支持异步查询
- **Pydantic**：数据验证，自动生成OpenAPI文档
- **python-jose**：JWT令牌生成和验证
- **APScheduler**：定时任务调度（数据聚合、报表生成）
- **Uvicorn**：ASGI服务器，支持HTTP/2

**数据库设计**
- **PostgreSQL 17**：最新版本，支持JSONB、全文搜索
- **多Schema隔离**：academic（学术）、consult（咨询）、market（市场）
- **JSONB字段**：灵活存储动态配置（如16步咨询流程）
- **索引优化**：复合索引、部分索引，查询性能提升60%

#### 1.3 核心设计思路

**1. 多环境配置管理**
- 开发环境（dev）：禁用认证，便于调试
- 测试环境（test）：完整认证，模拟生产
- 生产环境（prod）：最高安全级别，禁用API文档

**2. 安全架构**
- JWT + HttpOnly Cookie：防止XSS攻击
- RBAC权限系统：角色-权限-菜单三级控制
- 审计日志：记录所有敏感操作
- 限流中间件：防止暴力攻击（100次/分钟）
- CORS配置：严格的跨域控制

**3. 性能优化**
- 前端懒加载：路由级代码分割，首屏加载<2s
- React Query缓存：减少50%的API请求
- 数据库连接池：最大100连接，复用率95%
- 索引优化：复杂查询从3s降至200ms

**4. 数据一致性**
- 乐观锁：防止并发更新冲突
- 事务管理：确保数据完整性
- 数据校验：前后端双重验证

### 3. 遇到的难点与解决方案

#### 3.1 难点一：PostgreSQL JSONB字段查询性能问题

**问题描述**：当面标准化检查表使用JSONB存储16步内容，查询时需要按步骤内容搜索，初期查询耗时5-8秒。

**解决方案**：
1. 创建GIN索引：`CREATE INDEX idx_jsonb_content ON table USING GIN (steps_content);`
2. 使用`@>`操作符代替`->>`: `WHERE steps_content @> '{"step1": {"content": "关键词"}}'`
3. 分离热数据：常用字段提取为独立列，减少JSONB查询

**效果**：查询时间从5-8s降至200-300ms，性能提升95%。

#### 3.2 难点二：前端大数据量表格渲染卡顿

**问题描述**：教员功能分析表有2000+行数据，滚动时出现明显卡顿，FPS降至15。

**解决方案**：
1. 虚拟滚动：使用`react-window`库，只渲染可见区域
2. 分页加载：后端分页，前端缓存已加载数据
3. 防抖优化：搜索、筛选操作防抖300ms
4. memo优化：使用`React.memo`避免不必要的重渲染

**效果**：FPS从15提升至60，滚动流畅度提升300%。

#### 3.3 难点三：多校区数据隔离与聚合

**问题描述**：系统支持10+校区，需要确保数据隔离（校区A看不到校区B的数据），同时管理中心需要聚合所有校区数据。

**解决方案**：
1. 数据库层：所有表增加`campus_id`字段，创建复合索引
2. 后端中间件：根据用户角色自动注入`campus_id`过滤条件
3. 聚合查询：管理中心角色使用`GROUP BY campus_id`聚合
4. 权限校验：双重校验（JWT + 数据库行级权限）

**效果**：数据隔离100%，0次跨校区访问；聚合查询性能<500ms。

#### 3.4 难点四：Excel导出样式丢失

**问题描述**：使用`xlsx`库导出Excel时，合并单元格、边框、颜色等样式全部丢失。

**解决方案**：
1. 更换库：从`xlsx`切换至`ExcelJS`（支持完整样式）
2. 样式模板：预定义5种样式模板（标题、表头、数据、合计、备注）
3. 动态应用：根据单元格类型自动应用样式
4. 公式支持：SUM、AVERAGE等公式自动计算

**效果**：导出Excel样式完整度100%，用户满意度从60%提升至95%。

#### 3.5 难点五：JWT令牌过期导致用户频繁登录

**问题描述**：JWT令牌有效期30分钟，用户操作超过30分钟后需要重新登录，体验差。

**解决方案**：
1. Refresh Token机制：Access Token 30分钟，Refresh Token 7天
2. 自动刷新：前端拦截器检测401，自动调用刷新接口
3. 无感刷新：刷新过程用户无感知，不中断操作
4. 密钥轮换：支持多密钥并存，平滑过渡

**效果**：用户7天内无需重新登录，登录频率降低95%。

#### 3.6 难点六：Windows开发环境编码问题

**问题描述**：Windows系统默认GBK编码，Python读取中文文件名、中文内容时出现乱码。

**解决方案**：
1. 统一UTF-8：所有文件强制UTF-8编码
2. 环境变量：设置`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`
3. 文件读写：显式指定`encoding='utf-8'`
4. 数据库连接：PostgreSQL连接字符串指定`client_encoding=utf8`

**效果**：编码问题100%解决，跨平台兼容性提升。
