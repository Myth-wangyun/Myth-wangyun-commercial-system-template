# 前端桥接迁移到后端真源方案

## 2026-03-13 更新

### 学术部班级就业总结链路

- `frontend/pages/academic/campus/02-stu-employment/5-camps-class-employment-detail/class-employment-summary.tsx`
  已改为纯后端只读页，不再读取 `localStorage`，也不再监听 `storage` / `employmentSummaryUpdated`。
- 学术端“班级就业明细”本身就是只读教质部明细：
  `frontend/pages/academic/campus/02-stu-employment/5-camps-class-employment-detail/class-employment-detail.tsx`
- 学术端“班级就业总结”现在统一读取 `/class-employment-summary/`。
- 该后端接口的实际数据源优先级是：
  1. 教质部 `QT班级就业信息汇总表`
  2. 若汇总表无数据，则按教质部 `QT班就业信息表` 动态生成
  3. 仅当教质部无数据时，才回退学术历史表
- 因此当前真实链路已经变成：
  `教质明细 -> 教质汇总/后端动态汇总 -> 学术总结只读页`
- 旧的 `frontend/pages/academic/campus/01-core-data/2-campus-employment-goals-results/campusClassEmploymentInfoSingle.tsx`
  已删除。它原本会把汇总副本写入浏览器缓存，属于无现行入口的旧桥接页。

## 1. 问题定义

当前仓库里有一类功能并不是直接读取后端真源，而是读取浏览器里的 `localStorage`、`storageService` 或者由另一个页面先写入的前端缓存。它会带来三个直接问题：

- 用户必须先访问上游页面，下游页面才“看起来有数据”。
- 同一业务数据在浏览器、本地缓存、后端表里出现多份口径，容易不一致。
- 换浏览器、清缓存、换账号或多人协作时，页面结果不稳定。

这类链路应统一改成：`页面录入 -> 后端表 -> 后端聚合接口/视图 -> 下游页面只读`。

## 2. 迁移原则

1. 跨页面依赖只能依赖后端，不能依赖浏览器缓存。
2. `localStorage` 只允许保留为单页草稿缓存，不能再作为另一个功能的正式数据源。
3. 需要自动汇总时，把汇总逻辑放在后端 service / endpoint / view，不再靠 `storage` 事件或 `CustomEvent`。
4. 迁移时先替换下游读路径，再删除上游桥接写入，避免出现页面空白。

## 3. 优先迁移链路

### 3.1 学术部就业链路

现状：

- `frontend/pages/academic/campus/01-core-data/1-core-data-summary/2-employment-summary/service.ts`
  之前保留了“本地汇总存储优先”的兼容逻辑，导致目标页更新依赖浏览器缓存。
- 现在 `class-employment-summary.tsx` 已经切成纯后端只读，`campusClassEmploymentInfoSingle.tsx` 也已删除。
- 当前剩余问题集中在“学术部目标值维护页”还要继续去掉本地存储思路，统一按后端汇总口径读写。

目标：

- 上游明细页只保存后端班级就业明细表。
- 复用后端“班级就业汇总”接口，由后端按校区、班级、年月汇总，并叠加学术部目标值。
- 就业总结页只读该后端汇总接口；就业目标页只允许维护学术目标字段，不再依赖前置页面。
- 删除 `class_employment_summary_data`、`employmentSummaryUpdated` 之类的跨页桥接。

实施顺序：

1. 已完成：就业总结页改读后端汇总接口。
2. 已完成：删除旧桥接页和跨页缓存写入链路。
3. 进行中：让学术部目标页只维护目标值，并直接写回 `/class-employment-summary/`。
4. 后续：继续清理 `service.ts` 内未被现行页面使用的本地存储兼容方法。

### 3.2 学术管理中心核心汇总链路

现状：

- `frontend/pages/academic/mgnt/campus-level/1-campus-core-summary/index.tsx`
  仍直接从 `class_file_record_class_list` 和本页 `localStorage` 推导校区核心汇总数据。

目标：

- 班级数量、在校生人数、就业班级数等口径统一改为后端聚合接口输出。
- 管理中心页只负责筛选和展示，不再自行补空行、自动写本地缓存。

实施顺序：

1. 把现有前端推导字段拆成明确的后端口径字段。
2. 在后端增加校区核心汇总接口或视图。
3. 页面改成纯读取后端；确认稳定后删除本地自动补数逻辑。

### 3.3 配置型表头/规则缓存链路

现状：

- 薪资预估、压力面试、考试规则等页面，会把表头配置或计算规则保存在浏览器。
- 这类页面虽然不一定跨页联动，但会导致“换设备就丢”“多人看不到同一规则”。

目标：

- 表头模板、角色表头映射、计算规则改成后端配置表。
- 页面进入时先读后端配置；用户修改后持久化到后端。
- 本地缓存只做断网或未保存草稿。

优先页面：

- `frontend/pages/academic/campus/02-stu-employment/7-campus-salary-prediction/salary-prediction.tsx`
- `frontend/pages/academic/campus/02-stu-employment/10-class-exam-scores/022-exam-scores.tsx`
- `frontend/pages/academic/campus/02-stu-employment/12-class-press-interview-scores/023-project-defense.tsx`
- `frontend/pages/teaching-quality/campus/2-stu-emmplyment/4-class-salary-estimate/index.tsx`
- `frontend/pages/teaching-quality/campus/2-stu-emmplyment/10-class-pressure-interview-score/index.tsx`

### 3.4 企业文化与单页本地持久化链路

现状：

- 企业文化宣讲计划、企业文化考试计划这两张表已经接入后端读写，不是纯前端单机表单。
- 当前实现是“后端为主，本地缓存兜底”：
  - 页面进入时优先请求后端。
  - 后端无数据或请求失败时，回退读取 `localStorage`。
  - 保存时提交到后端，并同步写一份本地缓存。
- 因此这两张表已经具备多人共享的后端真源，只是还残留浏览器缓存兼容逻辑。

目标：

- 保持后端为唯一业务真源。
- 把 `localStorage` 降级为“临时草稿/失败回退”，不能与后端并列为正式来源。
- 如果确认线上后端稳定，可继续简化为“只读后端 + 可选未保存草稿缓存”，去掉历史兼容 key。

处理建议：

1. 保留当前后端 GET/POST 主链路。
2. 删除历史兼容 key 和无必要的本地回填逻辑。
3. 如果需要断网保护，只保留当前页面、当前校区、当前年月的未提交草稿，不再把本地缓存当正式数据副本。
4. 文档中不再把这两张表归类为“待补后端”的页面。

## 4. 删除规则

满足以下条件才直接删除：

- 该文件或页面不在当前可见菜单中。
- 路由、组件映射、测试清单里已无引用。
- 没有其他活跃页面 import 它的代码。

不满足以上条件的，不叫死代码，叫“活跃但架构落后”，应先迁移再删。

## 5. 推荐实施批次

### 批次一：已完成或可立即执行

- 删除无引用 bridge 适配器。
- 删除隐藏旧路由和对应旧页面。

### 批次二：最高优先级

- 学术部就业明细 -> 就业总结 -> 管理中心汇总，全部切到后端真源。

### 批次三：配置型页面

- 把表头、规则、模板类 `localStorage` 迁到后端配置表。

### 批次四：纯单页工具页

- 逐页确认是否需要多人共享。
- 需要共享的补后端；不需要共享的保留，但文档中明确标记为个人草稿页。

## 6. 验收标准

- 任何下游页面都不需要先打开上游页面才能显示正确数据。
- 清空浏览器缓存后，核心业务页数据不丢失。
- 同账号跨浏览器、跨机器看到的结果一致。
- 业务汇总页只依赖后端接口或数据库视图，不再依赖浏览器事件同步。
