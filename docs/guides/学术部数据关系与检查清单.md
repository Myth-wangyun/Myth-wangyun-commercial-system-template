# 学术部数据关系与检查清单

## 2026-03-13 更新

- 学术端“班级就业明细表”继续只读教质部明细。
- 学术端“班级就业总结”已改为只读后端 `/class-employment-summary/`，不再依赖浏览器缓存或先访问其他页面。
- `/class-employment-summary/` 的后端来源优先级为：
  1. 教质部 `QT班级就业信息汇总表`
  2. 教质部 `QT班就业信息表` 动态聚合
  3. 学术历史表回退
- 因此就业这条主链当前应按“教质录入明细 -> 后端汇总 -> 学术查看总结”理解，不再按前端 bridge 理解。

### 3.1 当前必须明确区分的三类页面

#### A. 已切后端聚合的只读页

- 管理中心核心业务数据汇总
- 学术部就业目标与结果汇总
- 班级就业明细
- 新生维稳统计
- 每日新生安排

证据：

- `frontend/pages/academic/mgnt/1-core-summary/service.ts`
- `frontend/pages/academic/campus/01-core-data/2-campus-employment-goals-results/campusClassEmploymentInfo.tsx`
- `frontend/pages/academic/campus/01-core-data/4-campus-stability-stats/components/MonthlyStabilityDetailReadOnly.tsx`
- `frontend/pages/academic/campus/04-stu-stability/18-new-student-schedule/NewStudentArrangementReadOnly.tsx`

#### B. 仍保留前端 localStorage/浏览器持久化的活跃链路

- `frontend/pages/academic/mgnt/campus-level/1-campus-core-summary/index.tsx`
- `frontend/pages/academic/campus/01-core-data/1-core-data-summary/2-employment-summary/service.ts`
- `frontend/pages/academic/mgnt/campus-level/4-student-stability/service.ts`

结论：

- 旧 bridge 适配器已经移除，学术端就业总结页也已经切到后端只读；剩余风险主要集中在核心汇总和个别管理页的浏览器存储依赖。
- 当前可见的管理中心核心汇总已经以 `service.ts` 的后端聚合接口为准，不能再把浏览器缓存当成权威源。

#### C. 前端持久化或单页独立页

- 班作业成绩表
- 班考试成绩表
- 听课成绩表
- 若干项目/评价类页面

结论：

- 这些页在源码中仍能看到 `localStorage` 读写或仅前端持久化逻辑。
- 检查时不要把这类页误判为“填了就会自动汇总到管理中心”。

## 4. 建议录入顺序

1. 先在配置中心维护班级，再进入教质部维护班级就业信息、维稳明细、每日新生安排。
2. 再回到学术部检查只读消费页：
   - `/campus-employment-goals-results-tabs`
   - `/campus-class-employment-detail`
   - `/campus-stability-stats`
   - `/campus-daily-new-student-schedule`
3. 需要学术部自己维护的数据，再录入本部门后端页：
   - 口碑报名/口碑目标与结果
   - 班排课表
   - 学员访谈记录表
4. 最后再处理前端持久化页：
   - 作业成绩
   - 考试成绩
   - 听课成绩
   - 其他单页评价类功能

## 5. 每类功能怎么检查

### 5.1 管理中心核心汇总

1. 打开 `/academic-mgnt-core-business-summary-all`。
2. 切年份，确认会重新请求核心汇总接口。
3. 对照 `frontend/pages/academic/mgnt/1-core-summary/service.ts`，确认入离职与师资配比字段一并变化。
4. 页面不应该提供直接保存底表数据的入口。

### 5.2 教质只读链路

1. 先在教质部修改一条班级就业信息、维稳明细或每日新生安排。
2. 打开学术部对应只读页刷新。
3. 核对学术页是否展示新值；若学术页无保存按钮，属于正常现象。

### 5.3 学术部后端录入页

1. 打开口碑招生、班排课、访谈记录等页。
2. 新增一条数据并刷新页面。
3. 若刷新后仍存在，说明是后端页；若只在当前浏览器存在，需要进一步看是否为前端持久化页。

### 5.4 前端持久化页

1. 在同一浏览器录入数据后刷新页面。
2. 再换浏览器或清空本地存储验证。
3. 若数据只跟随浏览器本地状态变化，不应把它写进“后端业务流向”。
