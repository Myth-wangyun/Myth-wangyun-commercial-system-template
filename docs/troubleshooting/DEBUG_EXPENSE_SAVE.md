# 费用投入保存问题 - 调试指南

## 问题现象

保存时费用投入显示为 0.0，而不是用户输入的值。

响应示例：
```json
{
  "费用投入": 0.0,  // ❌ 应该是用户输入的值
  "计划收入": 3.0,
  "计划招生": 1
}
```

## 已添加调试日志

按 `F12` 打开控制台（Console）

1. 在口碑页面找到任意咨询师的任意月份
2. 在"费用投入"列输入一个值（例如：5000）
3. **观察控制台输出**

- ✅ `value` 应该是你输入的数字（5000）
- ✅ `费用投入` 应该等于 value
- ✅ `changes` 对象中应该有 `费用投入: 5000`

## 可能的问题和解决方案

### 问题A: 输入时没有看到"费用投入变更跟踪"日志

**原因**: `handleUpdateConsultantMonthlyData` 没有被调用

**检查**:
1. 确保你在"口碑"标签下（只有口碑类型才启用编辑）
2. 确保不是在合计行编辑（合计行不可编辑）
3. 检查输入框的 `onChange` 是否正确绑定

**解决**: 刷新页面重试

### 问题B: 看到日志但 `value` 是 null 或 undefined

**原因**: InputNumber 返回值问题

**检查日志中的**:
```
value: null,  // ❌ 应该是数字
```

**解决**: 检查 InputNumber 组件的 onChange 参数

### 问题C: pendingPlanChanges 是空的

**原因**: setState 异步问题或条件判断失败

**检查**:
```typescript
if (typeof row.月份 === 'number' && row.咨询师) {
  // 这个条件是否满足？
}
```

**解决**: 
- 确保 `row.月份` 是数字类型（1-12）
- 确保 `row.咨询师` 不是空字符串

### 问题D: 保存时 changes.费用投入 存在但 dataItem.费用投入 是 0

**原因**: 条件判断问题

**当前代码**:
```typescript
费用投入: changes.费用投入 !== undefined ? changes.费用投入 : (existingRow?.市场投入 ?? 0)
```

**检查**:
- `changes.费用投入` 的值是什么？
- 如果是 0，`0 !== undefined` 为 true，应该使用 0
- 如果是 undefined，会使用 `existingRow?.市场投入 ?? 0`

### 问题E: 后端收到的数据中 费用投入 是 0

**原因**: API 请求参数问题

**检查**:
1. 打开浏览器 Network 标签
2. 找到 `/api/v1/consult/consultant-plan/batch` 请求
3. 查看 Request Payload

应该看到：
```json
{
  "数据列表": [
    {
      "年份": 2026,
      "月份": 1,
      "校区": "河北盛邦校区",
      "咨询师": "张三",
      "数据类型": "口碑",
      "计划收入": 3,
      "计划招生": 1,
      "费用投入": 5000  // ✅ 检查这里
    }
  ]
}
```

**如果这里是 0**：问题在前端构建数据时
**如果这里是正确的但响应是 0**：问题在后端

## 快速诊断流程

```
1. 输入 5000
   ↓
   控制台显示：费用投入变更跟踪 value: 5000
   ✅ 输入成功

2. 点击保存
   ↓
   控制台显示：pendingPlanChanges 包含 费用投入: 5000
   ✅ 变更跟踪成功

3. 查看构建数据项日志
   ↓
   dataItem.费用投入: 5000
   ✅ 数据构建成功
   ❌ dataItem.费用投入: 0 → 问题D

4. 查看 Network 请求
   ↓
   Request Payload 中 费用投入: 5000
   ✅ 发送正确
   ❌ Request Payload 中 费用投入: 0 → 前端序列化问题

5. 查看响应
   ↓
   Response 中 费用投入: 5000
   ✅ 保存成功！
   ❌ Response 中 费用投入: 0 → 后端问题
```

## 当前修复内容

### 修复1: 改进条件判断

**之前**:
```typescript
费用投入: changes.费用投入 ?? existingRow?.市场投入 ?? 0
```
问题: `??` 只检查 null 和 undefined，如果 `changes.费用投入` 是 0，仍会使用 0

**之后**:
```typescript
费用投入: changes.费用投入 !== undefined ? changes.费用投入 : (existingRow?.市场投入 ?? 0)
```
改进: 显式检查 undefined，允许保存 0 值

现在每个关键步骤都有日志输出，方便定位问题。
